Diagnóstico diferencial de dengue com dados clínicos

Uma introdução às árvores de decisão com registros de notificação do SINAN.

Profa. Patricia Takako Endo · Universidade de Pernambuco, CaruaruNo dotLAB · VALERIA

Quando alguém chega a uma unidade de saúde com febre e/ou dor no corpo durante uma epidemia de dengue, a equipe preenche uma ficha de notificação: quais sinais a pessoa tem, quando começaram, se tem alguma doença prévia. Só depois, às vezes, vem o exame laboratorial que confirma ou descarta a dengue.

E esse “às vezes” pesa. Segundo o Ministério da Saúde, citado no data paper da base de arboviroses do dotLAB1, apenas cerca de 23% dos casos foram testados em laboratórios de referência. No resto, a decisão depende das informações clínicas que estão no registro do paciente.

Então, nossa pergunta é: considerando apenas os sinais clínicos, uma máquina consegue classificar quem tem dengue de quem não tem? Em termos de aprendizado de máquina, queremos um classificador binário (binary classifier) treinado por aprendizado supervisionado (supervised learning): o modelo aprende com registros cujo desfecho já é conhecido. Para responder, vamos construir uma árvore de decisão, passo a passo.

Cada registro é uma instância (instance), descrita por atributos (features): os sinais clínicos. O desfecho, dengue confirmada ou caso descartado, é a classe ou rótulo (label), a variável-alvo (target) do modelo. Aqui, dengue é a classe positiva.

Um detalhe antes de começar: na base completa, 67% dos registros com desfecho são de dengue confirmada, um caso de desbalanceamento de classes (class imbalance). Um classificador da classe majoritária (majority-class baseline), que responde sempre “dengue”, já tem 67% de acurácia (accuracy), a proporção de acertos, sem aprender nada. Por isso, aqui usamos uma amostra balanceada, obtida por subamostragem (undersampling) da classe majoritária: assim, qualquer acurácia acima de 50% vem dos sinais clínicos do paciente.

Percorrer as duas árvores é parecido. O que torna a árvore de decisão um modelo de aprendizado de máquina é como as perguntas são escolhidas: elas são aprendidas a partir dos dados.

Primeiro, medir a impureza

Uma árvore de decisão realiza um particionamento recursivo binário (recursive binary partitioning) dos dados: em cada nó interno (internal node), aplica uma regra de divisão (split) sobre um atributo e separa as instâncias em dois nós filhos (child nodes). Para escolher a melhor regra, ela precisa medir o quanto as classes estão misturadas num nó: a impureza (impurity). Um nó só com dengue é um nó puro (pure node), com impureza zero; um nó meio a meio tem a impureza máxima.

As duas medidas de impureza mais usadas são a entropia de Shannon (Shannon entropy) e a impureza de Gini (Gini impurity). Arraste o controle e veja como as duas reagem.

Para um nó D com instâncias de k classes, sendo pi a proporção da classe i, as fórmulas gerais são:

H(D) = −Σi=1…k pi log₂ pi

G(D) = 1 − Σi=1…k pi²

Com duas classes, sendo p a proporção da classe positiva, elas ficam:

H(p) = −p log₂ p − (1 − p) log₂ (1 − p)

G(p) = 1 − p² − (1 − p)²

Daqui em diante usamos a entropia, e a divisão escolhida em cada nó é a de maior ganho de informação, como veremos a seguir; o raciocínio é o mesmo com a impureza de Gini. No DecisionTreeClassifier do scikit-learn, a escolha é feita pelo parâmetro criterion, que aceita "gini" (o padrão) e "entropy".

Uma regra de divisão de cada vez

Agora, a primeira divisão. Se testarmos o atributo exantema (“a pessoa tem exantema?”), as instâncias se dividem em dois nós filhos: o das que responderam sim e o das que responderam não. A divisão é boa se os nós filhos ficarem menos impuros que o nó pai (parent node).

Essa redução se chama ganho de informação (information gain): a impureza do nó pai menos a média das impurezas dos nós filhos, ponderada pelo número de instâncias em cada um.

IG = H(pai) − (nsim / n) H(sim) − (nnão / n) H(não)

O resultado é a primeira resposta à nossa pergunta. O atributo de maior ganho, a dor retro-orbital, reduz a entropia em cerca de 0,005 bit, menos de 1% do máximo possível. Ainda assim, ele carrega alguma informação: a probabilidade condicional (conditional probability) de dengue dado o sinal, P(dengue | dor retro-orbital), é de cerca de 61%, contra 48% quando o sinal está ausente.

Um cuidado de leitura: nessa tabela, “não” inclui os registros em que o campo ficou em branco. Isso equivale a tratar os valores ausentes (missing values) como negativos, uma forma simples de imputação (imputation). Entre registros totalmente preenchidos, as diferenças podem ser maiores.

A árvore cresce

Para construir a árvore inteira, o algoritmo repete esse processo de cima para baixo (top-down): escolhe a divisão de maior ganho, separa as instâncias e, em cada nó filho, procura de novo a melhor divisão. É um algoritmo guloso (greedy algorithm): em cada nó, fica com a melhor divisão local, sem rever escolhas anteriores. Essa é a ideia dos algoritmos clássicos ID3, C4.5 e CART; o scikit-learn implementa uma versão otimizada do CART. Os nós em que a árvore para de dividir são as folhas (leaves), ou nós terminais, e a regra que decide quando parar é o critério de parada (stopping criterion).

Em pseudocódigo, o algoritmo é recursivo:

GerarArvore(D, atributos)
  crie um nó N
  se todas as instâncias de D são da mesma classe C:
      retorne N como folha rotulada com C
  se atributos está vazio:
      retorne N como folha com a classe majoritária de D
  aplique a medida de seleção de atributos a (D, atributos)
      para encontrar o melhor critério de divisão
  rotule N com o critério de divisão
  se o atributo escolhido é discreto e divisões multivias são permitidas:
      remova o atributo de atributos
  para cada resultado j do critério de divisão:
      Dj ← instâncias de D que satisfazem j
      se Dj está vazio:
          anexe a N uma folha com a classe majoritária de D
      senão:
          anexe a N o nó retornado por GerarArvore(Dj, atributos)
  retorne N

Adaptado de Han e Kamber (2006)3.

As saídas antecipadas do pseudocódigo são critérios de parada naturais: o nó é puro, não há mais atributos para testar ou a partição ficou vazia. Há ainda um caso comum em dados reais: o nó continua impuro, mas nenhum atributo traz ganho. Registros com exatamente os mesmos sinais e desfechos diferentes não podem ser separadas por regra nenhuma, e o nó vira folha com a classe majoritária. Nos nossos dados, isso acontece o tempo todo.

Um dos critérios de parada mais usados é a profundidade máxima (max_depth), um hiperparâmetro (hyperparameter): um valor escolhido antes do treinamento, e não aprendido com os dados. Use o controle para aumentar a profundidade e acompanhe a acurácia em dois conjuntos: o conjunto de treinamento (training set), usado para construir a árvore, e o conjunto de teste (test set), com instâncias que ela nunca viu. A acurácia no teste estima o desempenho de generalização (generalization performance). Com a amostra real, a divisão é temporal: o treinamento usa as semanas epidemiológicas mais antigas e o teste, as seguintes.

Repare no que acontece com a árvore funda, principalmente com 300 instâncias de treinamento: a acurácia no treinamento sobe, mas a acurácia no teste não acompanha. A árvore passa a memorizar particularidades do conjunto de treinamento, como a combinação exata de sinais de poucas pessoas, em vez de aprender um padrão que generaliza. Isso se chama sobreajuste (overfitting) e está ligado à alta variância (high variance) do modelo: pequenas mudanças nos dados de treinamento mudam muito a árvore. No outro extremo, uma árvore rasa demais sofre de subajuste (underfitting), com alto viés (high bias). Escolher a profundidade é buscar o equilíbrio desse dilema viés-variância (bias-variance trade-off).

Como resumem Mayr et al.6, para evitar o sobreajuste, o objetivo do algoritmo não deve ser encontrar o melhor classificador para a amostra de treinamento, e sim a melhor regra de previsão para observações novas.

Limitar a profundidade antes do treinamento é uma forma de pré-poda (pre-pruning). A alternativa é a pós-poda (post-pruning): crescer a árvore inteira e depois remover os ramos que pouco contribuem, como faz a poda por custo-complexidade (cost-complexity pruning), disponível no scikit-learn pelo parâmetro ccp_alpha. Com mais instâncias de treinamento, o sobreajuste diminui, porque a variância cai.

Seguindo um registro

A grande vantagem das árvores é a interpretabilidade (interpretability): são modelos de caixa-branca (white-box), cuja decisão pode ser lida e auditada. Cada caminho da raiz à folha (root-to-leaf path) equivale a uma regra de decisão (decision rule), uma conjunção de condições do tipo “se A e não B, então dengue”. Imagine um registro e responda às perguntas da árvore de profundidade 3, uma de cada vez, começando pela raiz. A cada resposta, o caminho avança um nível.

A resposta vem acompanhada de uma probabilidade estimada (predicted probability) da classe positiva: a proporção de dengue entre as instâncias de treinamento que caíram na mesma folha. É o que o método predict_proba do scikit-learn retorna. Quando essa probabilidade fica perto de 50%, a árvore está dizendo que os sinais clínicos, sozinhos, não bastam. Saber se essas probabilidades correspondem às frequências observadas em dados novos é uma questão de calibração (calibration).

Forças e fraquezas

Resumindo o que vimos, com base em Chandramouli, Dutt e Das4.

Forças

  • Produz regras simples e compreensíveis: árvores pequenas podem ser lidas sem conhecimento matemático ou computacional avançado.
  • Lida com atributos numéricos e categóricos no mesmo modelo.
  • Funciona com conjuntos de treinamento pequenos e grandes.
  • Indica quais atributos são mais úteis para a classificação: os que aparecem perto da raiz, com mais ganho. No scikit-learn, essa informação está em feature_importances_.

Fraquezas

  • Tem viés para atributos com muitos valores possíveis: dividir em muitos nós pequenos tende a gerar nós mais puros, mesmo por acaso.
  • Sofre sobreajuste ou subajuste com facilidade, dependendo de onde a construção para.
  • Erra mais em problemas com muitas classes e poucas instâncias de treinamento.
  • Árvores grandes são difíceis de entender, e a interpretabilidade se perde.
  • As fronteiras de decisão são paralelas aos eixos: cada regra testa um atributo por vez. Uma fronteira curva ou oblíqua só pode ser aproximada por muitas divisões em escada.

O que a árvore nos ensinou

Nesta base, os atributos clínicos dos registros têm baixo poder discriminativo (low discriminative power) entre dengue confirmada e casos descartados. Nenhum atributo sozinho reduz muito a impureza, e uma árvore mais funda só melhora no conjunto de treinamento. Isso não é um defeito do método: é a árvore mostrando, de forma transparente, o que os dados permitem dizer.

Esse resultado conversa com o que a vigilância já sabe. Dengue, chikungunya e outras doenças febris começam de modo parecido, e o diagnóstico seguro depende de exame laboratorial. Um modelo útil, nesse cenário, talvez não seja o que dá a resposta final, mas o que apoia a triagem (triage), indicando quem testar primeiro. Para isso, em vez de classificar pela maioria da folha (um limiar de 50%), pode-se ajustar o limiar de decisão (decision threshold) aplicado à probabilidade estimada.

E quando a árvore recebe atributos mais informativos? Tanner et al.5 estudaram 1.200 pacientes que procuraram atendimento em até 72 horas após o início da febre, em Singapura e no Vietnã; 30,3% tinham dengue. Com um classificador C4.5 aplicado à temperatura corporal e a exames simples de sangue, a árvore distinguiu dengue de outras causas de febre com 84,7% de acurácia. O primeiro corte foi a contagem de plaquetas.

Vale ler esse número com o cuidado da abertura: com 69,7% de casos sem dengue, o classificador da classe majoritária já acertaria 69,7%, então a árvore acrescenta cerca de 15 pontos. Ainda assim, é muito mais do que os sinais clínicos conseguem nesta base. O método é o mesmo; o que muda é a informação contida nos atributos. Melhorar o modelo, muitas vezes, começa por melhorar os dados.

Três perguntas para levar para a aula:

  • Tratamento de valores ausentes: os registros com campos em branco devem ser removidas, imputadas como “não” ou tratadas como uma categoria própria? Como cada escolha muda a árvore?
  • Seleção de atributos (feature selection): que outras informações do registro, como a semana epidemiológica ou a idade, poderiam ajudar? Quais delas causariam vazamento de dados (data leakage), entregando o desfecho ao modelo, como o resultado de um exame?
  • Custo assimétrico de erro: se o objetivo fosse priorizar exames, seria pior um falso negativo (dengue classificada como descartado) ou um falso positivo (caso descartado classificado como dengue)? Como isso se traduz em sensibilidade (sensitivity) e especificidade (specificity)?

Glossário

Acurácia (accuracy)
Proporção de instâncias classificadas corretamente.
Algoritmo guloso (greedy algorithm)
Algoritmo que, em cada passo, faz a melhor escolha local sem rever escolhas anteriores.
Amostra balanceada
Amostra com o mesmo número de instâncias de cada classe.
Aprendizado supervisionado (supervised learning)
Aprendizado a partir de exemplos cujo rótulo é conhecido.
Atributo (feature)
Variável que descreve uma instância; aqui, cada sinal clínico.
Atributo categórico e atributo numérico (categorical and numerical features)
Atributo com valores em categorias, como alta, normal e baixa, ou com valores numéricos, como a temperatura.
Calibração (calibration)
Grau em que as probabilidades estimadas correspondem às frequências observadas.
Classe positiva
Classe de interesse do problema; aqui, dengue confirmada.
Classificador binário (binary classifier)
Modelo que atribui cada instância a uma de duas classes.
Classificador da classe majoritária (majority-class baseline)
Referência que prevê sempre a classe mais frequente.
Conjunto de teste (test set)
Instâncias não usadas no treinamento, reservadas para estimar o desempenho de generalização.
Conjunto de treinamento (training set)
Instâncias usadas para construir o modelo.
Critério de parada (stopping criterion)
Regra que define quando um nó deixa de ser dividido.
Desbalanceamento de classes (class imbalance)
Situação em que uma classe é muito mais frequente que a outra.
Desempenho de generalização (generalization performance)
Desempenho do modelo em dados que ele não viu no treinamento.
Dilema viés-variância (bias-variance trade-off)
Equilíbrio entre modelos simples demais (alto viés) e complexos demais (alta variância).
Entropia de Shannon (Shannon entropy)
Medida de impureza baseada na teoria da informação, em bits.
Especificidade (specificity)
Proporção de negativos reais classificados corretamente.
Falso negativo e falso positivo
Erro em que um positivo real é classificado como negativo, e vice-versa.
Folha (leaf)
Nó terminal da árvore, onde a classe é atribuída.
Ganho de informação (information gain)
Redução da impureza obtida com uma divisão, ponderada pelo tamanho dos nós filhos.
Hiperparâmetro (hyperparameter)
Configuração do modelo escolhida antes do treinamento, como a profundidade máxima.
Impureza (impurity)
Medida de mistura de classes num nó.
Impureza de Gini (Gini impurity)
Probabilidade de classificar errado uma instância sorteada do nó, rotulando-a ao acaso conforme as proporções do nó.
Imputação (imputation)
Substituição de valores ausentes por valores estimados ou padronizados.
Instância (instance)
Uma observação do conjunto de dados; aqui, um registro da tabela.
Interpretabilidade (interpretability)
Facilidade de um ser humano entender como o modelo chega a uma decisão.
Limiar de decisão (decision threshold)
Valor de probabilidade acima do qual a instância é atribuída à classe positiva.
Medida de seleção de atributos (attribute selection measure)
Critério que ordena os atributos para escolher a divisão, como ganho de informação, razão de ganho ou impureza de Gini.
Nó interno, nó pai e nó filho
Nó interno aplica uma regra de divisão; o nó dividido é o pai e os nós resultantes, os filhos.
Nó raiz (root node)
Primeiro nó da árvore, onde todas as instâncias entram.
Particionamento recursivo binário (recursive binary partitioning)
Divisão sucessiva dos dados em dois subconjuntos, aplicada de novo a cada subconjunto.
Poda (pruning)
Redução da árvore para evitar sobreajuste: antes do treinamento (pré-poda) ou depois (pós-poda).
Probabilidade condicional (conditional probability)
Probabilidade de um evento dado que outro ocorreu, como P(dengue | sinal).
Probabilidade estimada (predicted probability)
Proporção da classe positiva na folha em que a instância cai.
Profundidade máxima (max_depth)
Número máximo de divisões entre a raiz e uma folha.
Regra de divisão (split)
Teste sobre um atributo que separa as instâncias de um nó em dois nós filhos.
Rótulo (label)
Classe conhecida de uma instância; a variável-alvo do modelo.
Seleção de atributos (feature selection)
Escolha de quais atributos entram no modelo.
Sensibilidade (sensitivity)
Proporção de positivos reais classificados corretamente; também chamada de recall.
Sobreajuste (overfitting)
Quando o modelo memoriza o treinamento e generaliza mal para dados novos.
Subajuste (underfitting)
Quando o modelo é simples demais para capturar o padrão dos dados.
Subamostragem (undersampling)
Remoção aleatória de instâncias da classe majoritária para balancear as classes.
Valores ausentes (missing values)
Campos sem informação registrada.
Vazamento de dados (data leakage)
Uso, no treinamento, de informação que não estaria disponível no momento da previsão.
